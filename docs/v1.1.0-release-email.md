**Preview text:** PreflightAPI v1.1.0 — Unified error responses, new error codes, and maintenance mode

## HTML (paste into the Import HTML dialog)

Click the `</>` button in the editor toolbar, paste the HTML below, and click Import.

```html
<h1>PreflightAPI v1.1.0</h1>
<p>We've shipped a set of improvements focused on making error handling simpler and more predictable across the entire API.</p>
<h2>Unified Error Response Format</h2>
<p>This is the biggest change in v1.1.0. <strong>Every error — whether from the API gateway or the backend — now returns the same JSON shape:</strong></p>
<blockquote><p>{ code, message, timestamp, traceId, path }</p></blockquote>
<p>Previously, gateway errors (auth, rate limits, tier-gating) used different response formats than backend errors. You had to check for <code>statusCode</code>, <code>error</code>, or <code>code</code> depending on the source. That's gone — you can now parse every error with a single code path and switch on the <code>code</code> field.</p>
<p>See our updated <a href="https://preflightapi.io/docs/errors">Error Handling documentation</a> for the full reference and code examples.</p>
<h2>New Gateway Error Codes</h2>
<p>Gateway errors now use machine-readable <code>code</code> values instead of ad-hoc formats:</p>
<ul>
<li><strong>UNAUTHORIZED</strong> (401) — missing or invalid API key</li>
<li><strong>TIER_RESTRICTED</strong> (403) — endpoint not available on your plan</li>
<li><strong>RATE_LIMIT_EXCEEDED</strong> (429) — per-minute rate limit hit, includes <code>retryAfterSeconds</code></li>
<li><strong>QUOTA_EXCEEDED</strong> (429) — monthly quota exhausted, includes <code>quotaResetsAt</code></li>
<li><strong>BACKEND_UNAVAILABLE</strong> (502) — backend unreachable, safe to retry</li>
<li><strong>MAINTENANCE</strong> (503) — scheduled maintenance in progress, includes Retry-After header</li>
</ul>
<h2>New Backend Error Code</h2>
<ul>
<li><strong>NOTAM_NOT_FOUND</strong> (404) — returned when no NOTAM matches your query, complementing the existing <code>NOTAM_SERVICE_UNAVAILABLE</code> code</li>
</ul>
<h2>Maintenance Mode</h2>
<p>We've added a maintenance mode that activates during deployments and scheduled maintenance windows. During maintenance, the API returns <code>503</code> with code <code>MAINTENANCE</code> and a <code>Retry-After</code> header. The <code>/health</code> endpoint remains available so your monitoring can distinguish maintenance from an outage.</p>
<h2>What You Need to Do</h2>
<p>If your error handling currently checks for the old gateway response shapes (<code>statusCode</code>, <code>error</code> fields), you should update it to use the <code>code</code> field instead. The old fields are no longer returned.</p>
<p><strong>Before:</strong></p>
<blockquote><p><code>if (body.error === 'RateLimitExceeded')</code></p></blockquote>
<p><strong>After:</strong></p>
<blockquote><p><code>if (body.code === 'RATE_LIMIT_EXCEEDED')</code></p></blockquote>
<p>If you're only using the HTTP status code for error handling (not parsing the response body), no changes are required — all status codes remain the same.</p>
<h2>Updated Documentation</h2>
<p>Our <a href="https://preflightapi.io/docs/errors">error handling docs</a> have been fully rewritten to reflect the unified format, including updated code examples and a complete error code reference.</p>
<p>As always, if you have questions or run into issues, reply to this email or reach out at <a href="mailto:support@preflightapi.io">support@preflightapi.io</a>.</p>
<p>Happy flying,<br>The PreflightAPI Team</p>
```

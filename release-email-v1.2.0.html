What's New in v1.2.0

We've been busy building new features to help you get more out of PreflightAPI. Here's what's new.

NAVAID Database

You can now query the full FAA navigation aid database — VORs, VORTACs, NDBs, DMEs, TACANs, and more. The new /navaids endpoints let you:

  • Search & filter — Browse all NAVAIDs with optional search, type, and state filters
  • Look up by identifier — Fetch NAVAIDs by their NavId (e.g., DFW)
  • Batch lookup — Retrieve up to 100 NAVAIDs in a single call
  • Nearby search — Find NAVAIDs within a radius of any lat/lon coordinate

Each NAVAID includes frequencies, service volumes, VOR checkpoint data, and operational remarks. Available on Commercial Pilot plans and above. Read the docs →

Bidirectional Pagination

All paginated endpoints now support backward navigation. Every paginated response now includes two new fields:

  • previousCursor — pass this as ?cursor= to go back a page
  • hasPrevious — tells you if there's a previous page

No changes needed on your end to keep existing integrations working. Old cursors and existing code will continue to work as-is — the new fields simply default to null / false when not applicable.

Data Currency Headers

Every response from a data endpoint now includes freshness headers so you know exactly how current the data is:

  • X-Data-Currency — fresh or stale:warning / stale:critical
  • X-Data-Last-Updated — when the data was last synced
  • X-Data-Sync-Age-Minutes — minutes since last sync

Use these headers to detect stale data and alert your users proactively. Learn more →

Improved Error Responses

We've made error handling easier with two improvements:

  • Validation errors now include a validationErrors field with per-field error messages — no more guessing which parameter was wrong
  • Service outage errors (503) now include a service field identifying exactly which upstream service is unavailable

All errors — gateway and backend — now use the same unified format. See the error reference →
